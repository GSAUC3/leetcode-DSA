Simulation is one of the most important patterns in programming interviews because it teaches you **how to translate a real-world process into code**. Surprisingly, many Easy and Medium LeetCode problems are pure simulation, and even Hard problems often contain a simulation component.

---

# 1. What is Simulation?

Simulation means:

> **Implement exactly what the problem statement describes, step by step, without trying to find a mathematical shortcut.**

You're not looking for an optimized algorithm or a clever trick. You're simply **simulating the process**.

For example, if a problem says:

> "Move one step to the right. If you hit a wall, turn left."

You literally write code that does exactly that.

---

# Example

Suppose you're asked to rotate an array by one position.

Input

```
[1,2,3,4]
```

Output

```
[4,1,2,3]
```

Simulation thinking:

```
save last element

shift everyone right

put saved element in front
```

Notice you didn't derive a formula.

You simply followed the instructions.

# How to Recognize Simulation Problems

Ask yourself:

### Is the problem just asking me to imitate something?

Examples:

```
A robot walks.

A game is played.

A person moves.

A matrix rotates.

People enter and leave.

Objects collide.

Cards are shuffled.
```

If yes,

it's probably simulation.

---

### Are there no optimization keywords?

Simulation problems rarely ask

```
Maximum

Minimum

Longest

Shortest

Largest

Smallest
```

Instead they ask

```
Return the final state.
```

or

```
Return the resulting array.
```

---

### Does every step depend on the previous one?

Example

```
Start at (0,0)

Move right

Move up

Turn left

Move down
```

Every operation depends on the current state.

That's simulation.

# Common Mistakes

### 1. Off-by-one errors

```
i<n

vs

i<=n
```

---

### 2. Wrong update order

Changing the state before using the old value.

---

### 3. Forgetting boundary checks

Accessing

```
grid[-1][0]
```

or

```
nums[n]
```

---

### 4. Overwriting values

Not using temporary variables when needed.

---

### 5. Incorrect direction updates

Turning left when the problem says turn right.

---

### 6. Ignoring edge cases

Empty arrays, single elements, or commands that do nothing.

---

# A General Approach to Solving Simulation Problems

Whenever you see a potential simulation problem, follow this checklist:

1. **Identify the state**: What information changes over time? (e.g., position, direction, array contents, score)
2. **Initialize the state** from the input.
3. **Process each instruction** exactly in the order given.
4. **Update the state** after each step.
5. **Handle boundaries and edge cases** (array limits, grid edges, circular movement).
6. **Return the final state or required result**.
